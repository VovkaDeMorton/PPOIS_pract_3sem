# PPOIS_pract_3sem — Smart Home Event Bus

Курсовой проект по дисциплине «Программирование с использованием объектно-ориентированных средств» (ППОИС).

Тема: Разработка событийно-ориентированной системы автоматизации на C++ с использованием паттернов Observer, Strategy и Command на примере симулятора умного дома.

## 📋 Описание проекта

Проект представляет собой событийно-ориентированную систему автоматизации, состоящую из двух слоёв:

### 1. Ядро — EventBus (переиспользуемая библиотека)

Универсальная шина событий, которая не знает ничего о конкретных устройствах. Её задача — принимать события и рассылать их всем подписчикам.

Компоненты ядра:
- Event — абстрактный базовый класс для всех событий системы.
- EventListener — абстрактный интерфейс подписчика с методом onEvent().
- EventBus — ядро системы: хранит список подписчиков, принимает события и рассылает их.
- EventQueue — очередь отложенной обработки событий (для асинхронности).
- EventFilter — фильтр подписки (например, «подписаться только на события типа X»).
- Subscription — RAII-обёртка для автоматической отписки при уничтожении объекта.

Ключевая особенность: ядро полностью отделено от прикладной логики. Оно ничего не знает ни про лампы, ни про термостаты. Благодаря этому ядро можно переиспользовать в других проектах (например, в системе управления очками с камерой, микрофоном и голосовым интерфейсом).

### 2. Приложение — Симулятор умного дома

Надстройка над ядром, которая демонстрирует его применение на конкретной задаче.

Компоненты приложения:
- Device — абстрактный базовый класс для всех устройств.
- Конкретные устройства: Lamp, Thermostat, MotionSensor, DoorLock, Alarm.
- DeviceRegistry — реестр всех устройств системы.
- Rule — абстрактный класс правила автоматизации (matches() + execute()).
- Конкретные правила: IfMotionThenLight, IfTempAboveThenAC, ScheduleRule.
- RuleEngine — движок, который загружает правила и подписывает их на шину событий.
- Condition — абстрактное условие (EqualsCondition, GreaterCondition, TimeCondition).
- Action — абстрактное действие (TurnOnAction, TurnOffAction, NotifyAction).
- ConfigParser — чтение конфигурации правил и устройств из файла.
- Scenario / ScenarioManager — именованные наборы правил («Ночь», «Утро», «Отпуск»).
- Logger — система логирования с несколькими выводами (консоль + файл).
- CommandParser / Command — разбор команд пользователя из консольного меню.

Сценарии использования:
- «Если движение ночью → включить свет.»
- «Если температура > 28°C → включить кондиционер.»
- «Если движение при выключенной сигнализации → отправить уведомление.»
- «По будням в 7:00 → включить свет в спальне.»
